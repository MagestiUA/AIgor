# Концепція local-code-agent

**Початкова ідея.** Локальний агент у стилі Claude Code, заточений на *відносно слабку
локальну модель* (gemma4 / Qwen3-Coder через Ollama, 16 GB VRAM). Базова модель сама
не справляється з великими проєктами, тому агент не покладається на «довгу пам'ять»
моделі, а **виносить контекст у файли й сам його стискає**:

- планувальник дробить задачу на вузькі кроки, кожен крок — окремий короткий tool-loop;
- підсумок розмови (`agent/convo.py`) і нотатки тем (`agent/topics.py`) ведуться в
  файлах/сесіях і стискаються за бюджетом;
- великі вкладення читаються частинами з дайджестом (`read_attachment`);
- великі «непрозорі» блоки коду не проходять через модель (strip/restore).

**Поточний напрям (з листопада 2026).** Додано сильнішу віддалену модель
(Qwen3.8-27B на vLLM/H100, 256k контексту, надійні tool calls). Ця архітектура
лишається — як спосіб не втрачати контекст у великих проєктах, — але:

1. бюджети масштабуються разом з бекендом (`agent/limits.py`: LOCAL ↔ REMOTE),
   головна вимога для сервера — вміститись у 256k;
2. «милиці» під слабку модель (nudge, розбір просочених tool_calls, ретраї роздумів,
   дайджести дрібних файлів) спрощуються покроково, лише після живих прогонів;
3. бекенд і підключення (адреса/порт/ключ) задаються в Налаштуваннях — це готує
   збірку для інших розробників (пакування — після локального тестування).

**Точка повернення:** тег `gemma-final` — останній стан, налаштований під слабку модель.

## Рефакторинг 24-11-2026 (огляд архітектури)

- **Один цикл** `agent/steploop.py` для кроків коду, чату, аналізу й субагента; виконання плану — ядро
  `agent/plan_runner.py` (UI лише адаптер), той самий шлях без UI — `agent/headless.py` + `scripts/run_task.py`.
- **Пошук і читання за рядками**: `search`, `read_file(path, start_line, limit)`; точкова правка `replace_in_file`.
- **Один виклик планувальника** визначає тип запиту (answer / shell / clarify / choose / plan).
- **Пам'ять — файли**: `recall` (нотатки сесії + теми), службові теки читаються `read_file`/`search`; стиснутий
  результат тулу несе точну адресу оригіналу; підсумок розмови лінивий (свіжі репліки дослівно).
- **Порядок контексту під кеш префікса**: стабільне спочатку, план із результатами — в кінці.
- Тести — на продакшн-лімітах (`limits.production()`).

## Керування великими задачами (код-режим)

Фідбек: «чи можна зробити X?» → «так» → «роби» мало породжувати купу узгоджених викликів. Тепер:
- **«роби» розгортається** у схвалену пропозицію (повний текст попередньої відповіді, не підсумок);
  класифікатор наміру бачить, що було перед короткою реплікою (`agent/orchestration.py`);
- **великий план** (≥4 дій) завжди показується на схвалення;
- **кроки бачать результати попередніх** і список змінених файлів;
- **невдалий крок зупиняє план** і лишає його для відновлення («Виконати» продовжує з цього кроку);
- після останнього кроку — **звірка**: синтаксис змінених .py + перевірка узгодженості, з повтором
  проблемного кроку (не більше 2 раундів).
Далі (E): чекліст плану в правій панелі.
